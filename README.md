# Вики Rogue Shard

Статический сайт: главная страница с разделами и страницы снаряжения, где рядом
стоят ванильные значения и значения мода.

Открывать `docs/index.html` — обычным двойным щелчком, сервер не нужен.
Эта же папка раздаётся через GitHub Pages.

> В репозитории лежит только собранный сайт (`docs/`). Скрипты сборки и
> выгруженные из игры таблицы держатся локально, поэтому пересобрать вики можно
> на машине автора.

## Пересобрать

```
python build.py
```

Никаких зависимостей, только Python. Скрипт заново читает данные и переписывает
всё в `docs/`. Правки руками в `docs/` пропадут при следующей сборке — менять
надо исходники, перечисленные ниже.

## Откуда берутся данные

| что | откуда |
|---|---|
| ванильные статы | `data/vanilla/table_weapons.txt`, `table_armor.txt` |
| статы мода | `<мод>/Codes/table_weapons.gml`, `table_armor.gml` |
| названия предметов (RU/EN) | `data/vanilla/table_equipment.txt` |
| названия статов (RU/EN) | `data/vanilla/table_attributes.txt` |
| иконки | `<лут-редактор>/sprites/s_inv_*` |
| порядок статов | `data/vanilla/attribute_order.txt` |
| деление по билдам | подзаголовки `// ...` в модовых таблицах |

Модовые таблицы читаются **прямо из исходников мода**, так что любая правка
`table_weapons.gml` попадает в вики следующей же сборкой.

Внутри категории предметы разложены по билдам, а внутри билда — от низкого
тира к высокому. Порядок самих билдов табличный: его расставил автор мода.

Деление берётся не из отдельного
файла, а из самих таблиц мода: они уже размечены подзаголовками `// DEFENSIVE`,
`// SABERS`, `// RIDER SHIELDS` и подобными. Значит новая группа в таблице
появится в вики сама, а разъехаться с модом ей неоткуда.

Порядок статов — тот же, в каком их перечисляет игра: она задаёт его явно
списками `global.attribute_order_all` в `o_textLoader_Other_25`.
`tools/extract_order.py` разворачивает их в плоский список; запускать после
обновления игры вместе с выгрузкой таблиц.

Ванильные таблицы — выгрузка из `vanilla.win`. После обновления игры её надо
обновить:

```
cd C:\Users\Danylo\Desktop\RogueShardTools\TestHarness\Builder
dotnet run -- --export-tables "C:\Users\Danylo\Desktop\Rogueshard Wiki\data\vanilla" --no-mod
```

Колонки сопоставляются **по именам**, а не по номерам: у ванильной
`table_weapons` есть колонка `altGrip`, которой в модовой нет, и по номерам всё
разъехалось бы.

## Как читать цвета

| вид | значит |
|---|---|
| зелёный | полезный стат |
| красный | вредный стат |
| салатовый | стат появился в моде, или стал лучше |
| ярко-красный | вредный стат появился, или стало хуже |
| серый зачёркнутый | стат был в ванили, в моде его нет |
| фиолетовый | редкость Unique |

Нулевые статы не показываются вовсе: игра их в подсказке тоже не пишет, а в
таблицах пустая ячейка и 0 значат одно и то же. Поэтому «было 5, стало 0»
читается как убранный стат, а не как «0 (-5)».

Так же прячутся значения по умолчанию из `DEFAULTS` в `wiki/config.py` —
сейчас там дальность 1, общая для всего оружия ближнего боя. Но только когда
значение стоит по умолчанию с обеих сторон: поменяй мод дальность с 1 на 2, и
строка появится целиком.

У изменившихся статов рядом со значением стоит разница: `(+3)` салатовым, если
стало лучше, `(-1)` ярко-красным, если хуже. У вредных статов наоборот — рост
красный, снижение салатовое.

Тир и редкость при изменении показываются двумя строками: старое значение
зачёркнуто, новое под ним.

Прочность, цена, дальность и урон — абсолютные величины, поэтому идут без знака
и без окраски, как в подсказках самой игры. Разница у них всё равно подписана.
Отдельных колонок под урон и защиту нет: они такие же строки «Свойств», как и
остальное, и точно так же сравниваются.

## Что где лежит

```
build.py            запуск сборки
assets/             картинки вики (шапка раздела Gear)
wiki/config.py      что показывать: разделы, категории, какие статы «вредные»
wiki/tables.py      чтение таблиц обоих видов
wiki/model.py       сборка предметов и сравнение версий
wiki/render.py      HTML
wiki/style.css      оформление
tools/check.py      проверка: срабатывают ли все виды сравнения
tools/structure.py  что вообще лежит в таблицах
docs/               результат сборки (он же то, что раздаёт GitHub Pages)
```

Страницы в два уровня:

```
docs/index.html            все категории плитками, сгруппированные
docs/gear/swords.html      таблица предметов
```

### Добавить категорию или группу

Всё в `wiki/config.py`:

* `GROUPS` — содержание главной. Группа это `(заголовок, таблица, категории)`,
  категория — `(имя, поле, значение)`; четвёртым элементом можно закрепить
  иконку плитки: `("Swords", "Slot", "sword", "s_inv_arnasword")`. Без него
  иконка выбирается сама — обычный предмет наибольшего тира в категории.
* `INDEX_BANNER`, `INDEX_TITLE` — картинка и заголовок главной; картинка лежит
  в `assets/`.
* `INVERTED` — статы, у которых больше значит хуже. Признака в данных нет, так
  что новый такой стат надо дописать сюда, иначе он покрасится наоборот.

Иконки — спрайты из игры, и они крошечные (27x81, 54x54 и подобные). Поэтому в
`wiki/style.css` картинке задаётся размер коробки с `object-fit: contain`, а не
`max-width`: тот умеет только уменьшать, и иконки остались бы в натуральную
величину.

## Известные пробелы

* **Жезлов (Wands) в моде нет.** Модовая `table_weapons` заменяет ванильную
  целиком, а жезлы в неё не попали — их 37 штук, и в игре с модом они не
  существуют. В вики они поэтому не показываются вовсе.
* Вместе с жезлами из модовой таблицы выпали ещё четыре предмета: `Rebel Flail`,
  `Recruit Flail`, `Spiked Warclub` и `Guard Halberd Alt`.
* Вторые строки одного и того же предмета не показываются: шлемы с поднятым
  забралом («Open Joust Bascinet» при живом «Joust Bascinet») — 14 штук, и
  «Guard Halberd Alt», вторая хватка «Guard Halberd» (у них колонка `altGrip`
  ссылается друг на друга). Отсекаются только те, у кого рядом есть исходник:
  «Open Sentinet» и «Open Bascinet» пары не имеют и остаются как отдельные
  предметы.
* У одного предмета не нашлось иконки `s_inv_*` — на его месте пустая рамка.
* У 16 предметов нет локализованного имени в `table_equipment`; показывается
  внутреннее.
* Разделы кроме Gear ещё не сделаны — на главной их нет.
